## 6 blockers identificados no review

1. **Contradição estética frontal com `main`.** A branch `redesign/v2` já mergeou monkeytype-minimalista; PR propõe Spider-Verse neon. `CONSTITUTION §5` chamava Spider-Verse de "não-opcional" — conflito direto.
2. **Backend Spring hexagonal overkill** para ~4 experiências + ~5 projetos. `content-source.md` já é fonte canônica em Markdown; construir admin CRUD que edita banco quebra a própria `CONSTITUTION §2`.
3. **Planning theatre**: 74 docs antes de código; 11 ADRs decretadas em bloco na mesma data; slots de learning vazios pré-criados.
4. **Roadmap irreal**: 48 US × ~2h ≈ 6 meses solo se nada slippar. US-M6-02 em 3h monta prompt+valida+persiste+testa em 3 idiomas — impossível.
5. **Gaps críticos ausentes**: CI, E2E, migração EmailJS→backend (viola CONSTITUTION §9, estava só no backlog), LGPD (chat guarda IP + mensagens sem retenção/consent), a11y automatizada, backup, staging, analytics.
6. **IA — parte mais bem pensada, mas com furos**: rate-limit + budget + cache + mock OK; faltavam injection guardrails reais (não regex ingênua), aprovação humana no pitch (risco de declarações falsas), disclaimer visível.

## 3 decisões travadas em conversa (2026-09-17)

### D-001 — Portfolio dual-track (creator + dev-for-hire), não CV puro

Audiência-alvo pivotou: recrutador enterprise saúde → creator/influencer YouTube (principal) + dev-for-hire (secundário). Home creator-first, mas rotas `/work` e `/cv` mantidas com peso secundário.

### D-002 — Estética híbrida neo-brutalist

Nem monkeytype puro (esconde criatividade), nem Spider-Verse puro (arriscado). Base = monkeytype terminal-minimal (`main` já mergeada). Acentos = comic-book/graffiti (glitch RGB, halftone HUD, hard-shadow, onomatopeias) usados cirurgicamente — 1–2 por tela no máximo. Linguagem = **neo-brutalism** (tendência 2026 documentada).

### D-003 — Sem backend Java. Stack Next-only + Edge Functions

Cortar backend Spring Boot por completo. Chat = Route Handler Edge (Vercel AI SDK). Contato = Route Handler Node (Resend). Rate-limit/cache = Upstash Redis. Se demanda por vitrine técnica backend justificar depois, vai como **repositório separado** (`portfolio-api`), não como parte do portfolio principal.

### D-004 — Zero PII pessoal no repositório público (implícita, aplicada no rescope)

`content-source.md` e o PDF foram removidos. History reescrita antes do merge para garantir que a PII não sobreviva no `git log`. Contato passa a ser via linkedin público + formulário serverless.

## Nota para o "eu do futuro"

O PR original era um monumento — 74 arquivos, 3 governanças redundantes, backend hexagonal para 4 experiências, Spider-Verse não-opcional. Esse tipo de documento nasce da vontade de "fazer certo desde o começo" mas cobra o preço de bloquear qualquer coisa por meses. A versão curada aqui aposta no oposto: menos plano formal, mais direção clara, e US bem escritas apenas para o que vai ser executado nas próximas semanas.

Se você (Omar do futuro) abrir esta PR e sentir que o roadmap ainda é grande, corte de novo. Regra: um milestone só vira "próximo" quando o anterior está DONE. Se M0 empacar, congela M1 e não fica gerando trabalho no papel.
